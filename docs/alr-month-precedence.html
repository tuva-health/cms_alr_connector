Which ALR file decides each month?

Several Assignment List Reports (ALRs) cover the same months: the quarterly ALRs of a performance year overlap each other, the benchmark ALRs overlap the quarterlies, and the next performance year's reports overlap the current one. For each month the CMS ALR connector picks one governing file per ACO, and that file alone decides who is enrolled:

  1. Take the earliest performance year with a file that covers the month. A closed performance year is final, so a later year's reports never rewrite it.
  2. Within that year, take the last file in the order initial < Q1 < Q2 < Q3 < Q4 < benchmark. The benchmark ALR is last only within its own performance year.
  3. If the same period was delivered more than once, the later T-stamp wins.

A file covers the twelve months its EnrollFlag1..EnrollFlag12 map onto. A beneficiary the governing file does not list is not enrolled for that month, even if an earlier or later file lists them. A beneficiary the governing file lists with an EnrollFlag of 0 for a month is not enrolled that month either.

What the governing file supplies

The governing file supplies all of the month's ALR-sourced fields: enrollment status, risk scores and HCC flags, demographics, TIN/NPI attribution, and the Table 1-6 and 1-9 fields.

Two things come from CCLF, not from the ALR, and live in the Medicare CCLF connector (medicare_cclf_connector): CCLF's data_sharing_flag, which comes from the CCLF8 demographics, and the extension of eligibility past the last month an ALR covers. The choice of governing ALR doesn't affect either of them.

How to use this page

Pick a guided walkthrough below and click its steps in order. Each step delivers files, and the month-by-month result shows which file governs each month and who is enrolled. Hover over (or tap) a month to see why. Below that you can deliver any file yourself, redeliver it, and choose who each file lists.

This page reflects the connector's aalr_governing_file model as of the release it ships in. The months each file covers come from the connector's mssp_file_parameters seed, which is copied into this page (see the months each file covers at the bottom). Every beneficiary and file here is made up.
